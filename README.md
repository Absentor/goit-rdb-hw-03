# Домашнє завдання 3: SQL та аналіз даних

## Опис проєкту

Проєкт присвячений завантаженню, очищенню, типізації та дослідницькому аналізу даних за допомогою PostgreSQL і SQL.

У роботі використано датасет **Bank Marketing**, який містить інформацію про маркетингові кампанії португальського банку та результати телефонних контактів із клієнтами.

## Джерело даних

- **Назва:** Bank Marketing
- **Офіційне джерело:** [UCI Machine Learning Repository: Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank+marketing)
- **Файл:** `bank-full.csv`
- **Кількість записів:** 45 211
- **Кількість початкових колонок:** 17
- **Спосіб формування вибірки:** використано повний набір даних `bank-full.csv`, без додаткової вибірки або випадкового відбору рядків.
- **Роздільник CSV:** крапка з комою (`;`).

## Структура проєкту

- `ДЗ_3.py` — Jupyter Notebook із реалізацією завдання, SQL-запитами, результатами та висновками.
- `README.md` — опис проєкту та інструкції із запуску.

## Етапи роботи

1. Завантаження початкового CSV-файлу.
2. Створення staging-таблиці та імпорт даних за допомогою `COPY FROM STDIN`.
3. Створення типізованої таблиці з обмеженнями цілісності даних.
4. Перевірка кількості записів, дублікатів, пропущених і спеціальних значень.
5. Аналіз розподілу категоріальних змінних та статистик числових показників.
6. Виконання SQL-запитів для дослідницького аналізу даних (EDA).
7. Формування висновків щодо якості даних та можливостей їх подальшого використання.

## Як запустити проєкт

1. Відкрий `ДЗ_3.py` у Google Colab.
2. Переконайся, що доступний початковий файл `bank-full.csv` за шляхом, який використовує ноутбук.
3. Виконай клітинки ноутбука послідовно, починаючи з першої.
4. Дочекайся завершення імпорту даних, створення таблиць, перевірок і SQL-запитів.
5. Для повторного виконання всього проєкту скористайся **Runtime → Restart session and run all** та переконайся, що всі клітинки виконуються без помилок.

Ноутбук використовує PostgreSQL, а для завантаження CSV у staging-таблицю застосовується `COPY FROM STDIN`.

## Результат

У результаті створюються staging-таблиця з початковими текстовими значеннями та окрема типізована таблиця для подальшого аналізу. Виконуються перевірки якості даних, дослідницькі SQL-запити та формуються висновки щодо отриманих результатів.
